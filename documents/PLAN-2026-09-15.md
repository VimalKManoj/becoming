# Phase-by-phase learning plan

Status date: 15 September 2026. Initial scaffold scope is phases 0–1 plus a typed backend starting point. Checkboxes describe actual work, not the full PRD.

## Phase 0 — own the foundation

**Outcome:** an independent app and a readable project map.

- [x] Next.js, React, TypeScript, Tailwind, lint and test configuration.
- [x] Six independent routes and shared workspace shell.
- [x] Preserve original PRD and clickable prototype in documents.
- [x] Write architecture, data model, approach and release plan.
- [x] Add environment template and contribution guidance.

**Learn:** App Router layouts, client boundaries, CSS tokens, dependency lockfiles.

**Read:** `src/app/layout.tsx`, `src/app/[section]/page.tsx`, `src/app/globals.css`.

**Exercise:** change spacing and typography, then add one route without changing recommendation logic.

**Gate:** independent install, typecheck, lint and production build pass.

## Phase 1 — make one evening work

**Outcome:** choose a focus → start → recap → reload and resume.

- [x] Capacity and energy choices with deterministic recommendations.
- [x] Concrete task creation, blockers and defined smaller steps.
- [x] Save a session once, retain partial progress and capture a next step.
- [x] Persist the active session and history in a validated browser workspace.
- [x] Add/brainstorm/activate an idea.
- [x] Show actual session history, weekly counts and evidence links.
- [x] Export a versioned local backup.

**Learn:** pure functions, state transitions, forms, runtime validation, browser hydration.

**Read:** `src/domain/workspace.ts` → `src/lib/local-store.ts` → `src/components/workspace-screen.tsx`.

**Exercise:** add a meaningful recommendation test and change one interaction.

**Gate:** partial-step completion leaves the parent open; repeat saves do not duplicate credit; reload preserves work. This gate applies to local mode only.

## Phase 2 — learn Convex through a real vertical slice

**Outcome:** authenticated tasks and sessions stored in Convex, reacting across tabs.

- [x] Starter schema, indexed owner-scoped task list/create and full-task recap mutation.
- [x] Fail-closed identity/ownership helpers and issuer config.
- [ ] Select auth provider and create a development Convex project.
- [ ] Generate official API/server types with the CLI.
- [ ] Connect authenticated React providers and sign-in/out screens.
- [ ] Complete server-backed session start/cancel and smaller-step behaviour.
- [ ] Replace local reads/writes for Today and Work with queries/mutations.
- [ ] Test ownership, invalid input, dependency checks, replay and transaction results.
- [ ] Verify two accounts cannot access each other's data.
- [ ] Decide and implement an explicit local-data migration.

**Learn:** schema validators, document IDs, indexes, queries vs mutations, identity, reactive subscriptions.

**Exercise:** create one task in the dashboard, retrieve it with a query, then create the next through a validated mutation. Change a record in one tab and observe the other.

**Gate:** real sign-in and cloud persistence are verified; local data is never silently mixed into an account. Do not deploy publicly before this gate.

## Phase 3 — organise a growing body of work

**Outcome:** projects, milestones and notebooks remain manageable.

- [ ] Full create/edit/archive for projects, milestones, ideas and tasks.
- [ ] Persist idea activation and brainstorm fields in Convex.
- [ ] Define/edit smaller steps and dependency validation without cycles.
- [ ] Split the initial screen component into feature modules.
- [ ] Add pagination and genuine empty/loading/error states for cloud queries.

**Learn:** document relationships, bounded queries, derived project progress, component composition.

**Exercise:** link an idea to a project milestone without duplicating its original notes.

**Gate:** archived/blocked work stays out of Today and no dangling references remain.

## Phase 4 — motivation and evidence

**Outcome:** useful weekly momentum and a publishable proof collection.

- [ ] Historical weekly target snapshots, effective dates, planned pauses and streaks.
- [ ] Timezone edge cases, backdated edits and deduplicated milestones.
- [ ] Artifact draft/ready/published statuses and portfolio-candidate flags.
- [ ] Optional uploads and reduced-motion completion celebration.
- [ ] Complete export/restore, error recovery and account data controls.

**Learn:** temporal modelling, immutable history, uploads, accessible motion and data portability.

**Exercise:** test a missed week, a paused week and a target change without rewriting prior awards.

**Gate:** no invented progress, duplicate awards or silently changed historical targets.

## Phase 5 — use it, redesign it, share the learning

**Outcome:** two weeks of real use improve the product.

- [ ] Track recommendation acceptance and swap reasons locally or through deliberate analytics.
- [ ] Refine the screens and mobile layout based on actual use.
- [ ] Verify keyboard flows, contrast, focus management and reduced motion.
- [ ] Capture a case study: initial constraint → design choice → implementation → evidence → iteration.

**Learn:** usability evaluation, performance profiling and communicating design trade-offs.

**Gate:** the tracker saves planning effort and produces finished work across lanes.

## Phase 6 — friends and open-source release

**Outcome:** other people can install or use their own private workspace.

- [ ] Choose a license, repository visibility and contribution model.
- [ ] Run multi-account regression tests and complete account deletion/export.
- [ ] Add CI, setup troubleshooting, demo screenshots and deployment instructions.
- [ ] Deploy a production frontend and separate Convex production deployment.
- [ ] Invite a small group of friends and collect feedback.

**Gate:** fresh-clone setup works, no credentials or personal content are tracked, and personal data stays private.

## Phase 7 — optional connections

Structured assignment import, ChatGPT scheduled-task integration, context export, GitHub/Figma references and publishing helpers. Re-evaluate only after the core workflow proves useful. No model API is required by the current architecture.

## Your next learning session

Run the app, finish one small session and reload. Read `recommend()` and `finishSession()`, then follow the Convex setup guide. Bring one concrete question from that trace into the next build session.
